# Крила — сайт продажу авіаквитків

Двосторонній вебсайт українською мовою: клієнтська частина для покупців і захищена
адміністративна панель. Це перший етап: архітектура, база даних, авторизація та основний
інтерфейс. Реальні постачальники рейсів (GDS) і платіжний сервіс ще не підключені —
замість них працюють локальні реалізації з тестовими даними.

## Запуск

Потрібен Node.js 20 або новіший.

```bash
npm install
```

```bash
npm run db:setup
```

```bash
npm run dev
```

Сайт відкриється на http://localhost:3000, адмін-панель — на http://localhost:3000/admin.

`db:setup` створює базу `prisma/dev.db` і наповнює її довідниками, тарифами та
демонстраційним розкладом на 60 днів уперед. Коли розклад застаріє, запустіть
`npm run db:seed` ще раз: рейси без бронювань буде створено заново.

Логін і пароль головного адміністратора беруться з `SEED_ADMIN_EMAIL` та
`SEED_ADMIN_PASSWORD` у файлі `.env` (зразок — `.env.example`).

## Технології

Next.js 16 (App Router, Server Actions) · TypeScript · Tailwind CSS 4 · Prisma 6 · SQLite.
Перехід на PostgreSQL — це зміна `provider` у `prisma/schema.prisma` та `DATABASE_URL`.

## Структура

```
prisma/schema.prisma        схема бази даних
prisma/seed.ts              довідники, адміністратор, демонстраційні рейси
src/app/(site)/             клієнтська частина
src/app/admin/              адмін-панель
src/app/actions/            серверні дії (форми)
src/components/             компоненти інтерфейсу
src/lib/                    бізнес-логіка
src/lib/providers/flights/  постачальники рейсів (інтерфейс + локальна база)
src/lib/providers/payments/ платіжні сервіси (інтерфейс + тестова оплата)
```

### Клієнтська частина

| Адреса | Сторінка |
| --- | --- |
| `/` | Головна з формою пошуку |
| `/search` | Результати пошуку, фільтри, сортування |
| `/flights/[id]` | Інформація про рейс і вибір тарифу |
| `/booking` | Дані пасажирів, додаткові послуги, промокод |
| `/checkout/[orderId]` | Оплата |
| `/confirmation/[orderId]` | Підтвердження бронювання |
| `/cabinet` | Профіль і зміна пароля |
| `/cabinet/bookings` | Мої бронювання, скасування й повернення |
| `/ticket/[bookingId]` | Маршрутна квитанція (друк / PDF) |
| `/support` | Запитання та контакти |
| `/login`, `/register` | Вхід і реєстрація |

### Адмін-панель

Огляд зі статистикою продажів, замовлення, бронювання, клієнти, платежі, рейси,
авіакомпанії, аеропорти, тарифи та додаткові послуги, промокоди, адміністратори,
налаштування (сервісний збір, знижки, контакти).

Ролі описані в `src/lib/permissions.ts`:

- **Підтримка** — лише перегляд замовлень, бронювань, клієнтів і рейсів.
- **Менеджер** — керування замовленнями, клієнтами, рейсами, довідниками, тарифами, промокодами.
- **Головний адміністратор** — усе, включно з налаштуваннями та співробітниками.

Права перевіряються на сервері на кожній сторінці та в кожній дії (`requireStaff`).

## Як влаштовані ціни

- Суми зберігаються в копійках, валюта — гривня.
- Ціна дорослого = базова ціна рейсу × множник тарифу. Діти та немовлята отримують знижку з налаштувань.
- Сервісний збір агенції — відсоток від вартості перельоту плюс фіксована частина.
- Умови тарифу копіюються в бронювання, тому зміна тарифу не впливає на вже продані квитки.
- Місця списуються під час оплати й повертаються в продаж після скасування.

## Підключення реальних сервісів

**Рейси.** Реалізуйте інтерфейс `FlightProvider` (`src/lib/providers/flights/types.ts`),
зареєструйте його в `index.ts` і вкажіть назву у `FLIGHT_PROVIDER`. Зараз бронювання
посилається на рейс у власній базі; для GDS знадобиться зберігати в бронюванні
ідентифікатор пропозиції постачальника та створювати бронювання через його API.

**Оплата.** Реалізуйте `PaymentProvider` (`src/lib/providers/payments/types.ts`) і вкажіть
назву в `PAYMENT_PROVIDER`. Реальний сервіс має вести покупця на власну платіжну сторінку
та підтверджувати платіж через webhook — для нього потрібно додати обробник у `src/app/api/`.
Сайт не приймає і не зберігає дані карток.

## Що ще не зроблено

- Реальні API рейсів і оплати, листи з підтвердженням на пошту.
- Рейси «туди й назад» (схема це дозволяє: у замовленні може бути кілька бронювань).
- Англійська версія сайту, керування контентом сторінок з адмін-панелі.
- Відновлення пароля, підтвердження пошти, обмеження кількості спроб входу.
- Автоматичне повернення коштів пасажирам після скасування рейсу адміністратором.
- Шифрування паспортних даних у базі та політика їх зберігання — обов'язково до запуску з реальними клієнтами.
